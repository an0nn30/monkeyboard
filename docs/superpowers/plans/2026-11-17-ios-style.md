# iOS Keyboard Style

Goal: selectable Default and iOS styles in Appearance, preserving the existing keyboard behavior.

References: Dustin’s November 17 screenshots at 11:27:23, 11:27:56, 11:28:21 and 11:30:45. Microphone space belongs to Space. Keep the host background transparent; use public UIKit controls, no Siri or dictation placeholders. Simulator testing only.

Implementation:
- Persist KeyboardStyle in the shared keychain. Appearance picker and light/dark previews use the same renderer as the extension. Default remains the initial selection. iOS uses system typography and neutral key colors; saved custom font/tint remain available in Default.
- Add iOS metrics for cover, unfolded portrait, landscape and one-handed widths: rounded caps, larger gaps, blank extended spacebars, native-like action glyphs, and detached pressed-key preview. Retain optional Y/B duplicates, letter hit regions, touch behavior and glide geometry.
- Keep Hide Keyboard accessible from the menu; preserve all number/symbol/emoji and host-specific key behavior.
- Capture the Apple keyboard and MonkeyBoard in the same simulator host. Verify Appearance persistence, typing/deletion/space/symbols, joined/split transitions, light/dark and popup shape. Run existing surface regression checks. Leave iOS selected on the Duo simulator.

Review focus: stale geometry on style/layer changes; transparent gaps and pressed-state restoration; narrow widths; contextual return/URL keys; shared setting reload when returning from Appearance.

Implementation and verification notes:
- Added the shared style setting and real-renderer previews. Default preserves the saved tint/font. iOS uses a neutral palette, system lettering, rounded caps, extended Space, native G/V split repeats (the optional Y/B setting remains available), and a detached popup.
- Compared real Apple and MonkeyBoard captures on the Duo simulator in cover light mode and unfolded landscape dark mode. Measured the native landscape key pitch, split-bank positions, bottom row, and prediction strip. Added separate cover/portrait/wide metrics.
- The iOS surface matrix covers 320, 452, 655, 801 and 951pt widths, eligible one-handed/split layouts, Y/B variants, letters/numbers/symbols/keypad, key hit targets and detached popups. The existing material/transparency and split-touch checks also pass.
- UI tests exercise style persistence, Default restoration, letter/Space/Delete/Return, returning from symbols, split/join menu state, and hiding the keyboard. Numeric-field integration was also checked on the simulator.
- Simulator artifacts and build/test logs are under `/tmp/monkeyboard-ios-style`. The Duo inner display requires `simctl io ... screenshot --display=3`; XCTest app screenshots of that display are black.
- One diagnostic comparison run crashed inside Apple's `UIKeyboardLayoutStar activationIndicatorView` when switching back to Apple's split keyboard. The native reference was captured successfully before that; subsequent MonkeyBoard-only runs are checked independently.
- Public-extension differences remain: MonkeyBoard's prediction/options toolbar replaces Siri, and its options button stays within the extension's hosted bounds. Top-row popups fit the available toolbar headroom. Dictation room is deliberately assigned to Space as requested. This is a close visual reproduction, not an assertion of pixel identity for system-owned UI.
- No physical-device tests, installation, GitHub publication, or changes to another session's work were performed for this task.
